## Today

Atlas is a deploy-anywhere text-to-SQL data analyst agent that connects to a customer's database, reads a YAML-defined semantic layer, and answers data questions in chat. The hosted SaaS at [app.useatlas.dev](https://app.useatlas.dev) runs across three regions (US/EU/APAC) with per-region data residency, per-workspace BYOT model configuration, and Vercel-sandbox-isolated explore/python tools.

The product spans a chat UI, an embeddable React widget, an OAuth-2.1 MCP server at [mcp.useatlas.dev](https://mcp.useatlas.dev) with a self-serve `start_trial` signup front door, a dashboard surface with draft/published mode, multi-environment query routing across connection groups, and eight chat-platform adapters (Slack live; Teams/Discord/Telegram/WhatsApp/Linear/GitHub/Google Chat wired). The **Company Atlas** ([ADR-0036](../../docs/adr/0036-atlas-as-company-brain.md), renamed from *Company Brain* by [ADR-0038](../../docs/adr/0038-the-atlas-is-the-product-the-brain-is-the-category.md)) is three milestones in — fail-closed ACL'd facts extracted from chat, Zoom transcripts and Outlook mail, with human-gated supersession and bi-temporal reads; extraction has been ON in all three prod regions since 2026-07-30. Proactive chat (reaction-first answers to natural questions) ships behind an enterprise gate. CRM lead capture pipes demo/signup/sales-form/Stripe-conversion events to a Twenty CRM at crm.useatlas.dev via a durable outbox. The CLI ships an operator surface for tenant data ops, a profiler, and a migrate tool.

The codebase is Hono + Next.js + TypeScript + Effect.ts + Vercel AI SDK + bun, organized as a 9-package monorepo with 20 plugins and three deploy modes (Docker, Vercel standalone, Railway). Enterprise features live under `ee/` behind a Context.Tag inversion that lets core compile and ship standalone. AGPL for self-host + commercial license for `ee/`; the hosted SaaS is the primary commercial offering.

Every fix carries a regression test verified to FAIL without it — including a real-Postgres test for `logUsageEvent`'s INSERT, which mocks structurally cannot cover (fire-and-forget write; the circuit breaker disables all metering after 5 failures).

**Shipped 2026-07-28 — the gateway catalog is awaited once per turn** ([#4872](https://github.com/AtlasDevHQ/atlas/issues/4872), PR [#4875](https://github.com/AtlasDevHQ/atlas/pull/4875)): the spin-out above, taken. `agent-compaction.ts` claimed the trigger "runs inside `prepareStep` on every step and cannot await" — false; `resolveCompactionSettings` is reached once per turn from an already-`async` scope in `runAgent`, and `prepareStep` only consumes the resolved value. That false premise was the entire justification for the `peekModelContextWindow`/`warmGatewayCatalog` pair, and it is what let the warm drift below the static table. One `await` retires all four moving parts: `lookupModelContextWindow` now fetches on a cold cache (live window on turn **1**, not turn 2+), air-gap gated on the `/` id shape, racing a **1.5s hot-path budget** against the static fallback so a slow or unreachable gateway can never delay or fail a turn — the fetch's own 10s ceiling stays where it belongs, in front of the admin picker. The pricing path keeps its sync per-row reader and awaits one `primeGatewayCatalog` before the fold instead.

Review (two rounds, four specialists each) surfaced three things worth recording. `contextWindowSource` reported `"catalog"` for BOTH the live gateway and the static family table — so the same model could resolve 1M on one turn and 200k on the next and be indistinguishable in telemetry or in a test; split to `"gateway"`/`"static"` and now logged, which is what makes the tier ordering unable to regress silently again. The catalog was being awaited even with compaction **disabled** — the shipped default — so every default deploy would have paid up to 1.5s on the hot path for a number `shouldCompact` short-circuits past; the network tier is now gated on `enabled`. And retiring the fire-and-forget warm silently removed the only `log.warn` on the caller side of the load, so a merely SLOW gateway would have reinstated the original bug invisibly; budget-elapsed and uncatalogued-model faults are now warned, deduped per cache-fill attempt and per model id. Separately, `platform-demo.test.ts` was found making a live call to `ai-gateway.vercel.sh` and pricing an assertion off Anthropic's published rate — green only because the live haiku price happened to equal the static family rate. Every guard was verified by breaking the implementation and confirming the specific test goes red, including the per-STEP regression (6 fetches vs 1).
